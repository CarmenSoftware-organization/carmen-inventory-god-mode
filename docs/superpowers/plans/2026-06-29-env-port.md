# Env-driven dev/start port (`PORT` in `.env.*`) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Source the dev/start server port from a `PORT` env var (3305) instead of hardcoding `-p 3305` in the scripts.

**Architecture:** Add `PORT=3305` to every env file; remove `-p 3305` from `dev:local`, `dev:prod`, and `start`. `next dev`/`next start` resolve the port as flag → `PORT` env → default 3000, so with the flag gone, `PORT` (injected by `bun --env-file` for dev, or bun's auto-loaded `.env.local` for start) drives it. Net behavior is unchanged: still 3305.

**Tech Stack:** bun 1.3.x, Next.js 16.2.9.

## Global Constraints

- Port value is **3305** in all env files — copied verbatim from the spec.
- bun only — no new dependencies.
- `.env`, `.env.local`, `.env.prod` are **gitignored**: edit them on disk but do NOT `git add` them. Only `package.json`, `.env.example`, `README.md`, `CLAUDE.md` are committed.
- Editing the real `.env*` files is **append-only** — never rewrite or reorder existing lines (they hold real secrets).
- Do not change `build`, the `dev` alias, or Playwright's hardcoded 3305.

## Notes for the implementer

- Next resolves the port as `-p` flag → `PORT` env → default 3000 (`node_modules/next/dist/docs/01-app/03-api-reference/06-cli/next.md:70`). Removing `-p` is what lets `PORT` take effect — do not re-add a flag.
- `bun --env-file` loads ONLY the named file, so `PORT` must be in `.env.local` AND `.env.prod`, or that environment silently falls back to 3000. Step 6 guards this.
- Do NOT start a dev server (it blocks); the controller runs the boot smoke separately.

## Controller post-implementation verification (not a subagent task)

- Bounded boot smoke: background-start `bun run dev:local`, poll `curl http://localhost:3305/login` until it returns a non-000 HTTP code, then stop the server — confirms `PORT` actually drives the port with no `-p` flag.
- `bun run typecheck` and `bun run test` still green.
